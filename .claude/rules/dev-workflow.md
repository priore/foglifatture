# Dev workflow

- Backend runs as a persistent background process on port 1969, serving `frontend/dist/` statically — no frontend dev-server hot-reload in this setup. After building the frontend, or after any backend code change, the running node process must be killed and restarted to pick up changes — it won't do so on its own. Restart directly without asking for confirmation: `lsof -i :1969 -sTCP:LISTEN -t` to find the PID, kill it, `nohup node src/server.js &` to relaunch.
- `AI-Workspace/` holds structured analysis/product docs, indexed by `AI-Workspace/WORKSPACE_MANIFEST.md` (see `PROJECT_CONTEXT.md`, `ARCHITECTURE.md`, `UI_ANALYSIS.md`, `FEATURE_PROPOSALS.md`, etc.). These are analysis-only — no code changes there. Before investigating code structure/architecture, check these docs first instead of a full-project scan. Exception: when a completed feature originated from a numbered entry in `FEATURE_PROPOSALS.md` (or an issue in `KNOWN_ISSUES.md`), update that entry immediately (✅ implemented, date, commit) as the last step of the task — don't leave it stale.
- **After completing backend logic changes** (new/changed function in `backend/src/services/*Service.js` or `backend/src/lib/*.js` with non-trivial branching), add or update a `*.test.js` using Node's built-in `--test` runner, matching the existing `pecService.test.js` pattern (see `.claude/rules/code-quality.md`). Skip for pure routing/wiring changes, frontend-only changes, or trivial one-line fixes.
- Root `CHANGELOG.md` (Keep a Changelog format, public — this is the GitHub-facing changelog) must be updated in the same commit as any user-facing change (feature, fix, behavior change). Entry text is written in Italian, matching the rest of the changelog. Add the entry under `## [Unreleased]`; only move it under a dated heading when the user says a release/version is being cut. Keep entries essential — one line per change, no commit-by-commit detail. Skip anything not relevant to a desktop end user (the changelog covers the desktop app only; changes confined to other clients are not logged): pure-internal changes (refactors with no behavior change), `AI-Workspace/` doc updates, README/config/tooling-only edits, and internal implementation detail (specific error codes, field/function names) unless it's the clearest way to describe the fix.
- **`AI-Workspace/Plans/` is self-contained.** Plans are private and removed by `sync-public`: nothing outside the folder (source comments, public docs, `AI-Workspace/product/`, `CHANGELOG.md`, README) may name or link a plan document or its sections (`PAGAMENTI_BTC.md F3`, `REGISTRO_LOTTI_BTC §4`, `Plans/…`). Comments state the rule in place; use FP-/K-ids instead of plan names. Only maintainer-only operational instructions in `.claude/rules` and `.claude/skills` (e.g. "update the row in the Apple backlog", social scripts) may point to a plan. Plans stay in the root only while still to start or to finish: completed ones go to `Plans/completati/`, discarded or not feasible ones to `Plans/scartati/`.
- **`AI-Workspace/Plans/PIANI_APERTI.md` is always kept current.** In the same commit that closes any phase of any plan in `Plans/` root, update it: remove or mark the closed phase, drop the plan's entry when it moves to `completati/` or `scartati/`, and re-check the execution order if the closure unblocks other items. Killer features (widespread in the market or missing from competitors, highly requested) always come first in the order. It is a Plans file, so it follows the self-contained rule above.
- **Tests and visual checks never run against the real instance.** Port 1969 and the real data folder (`backend/data`, the data pointer, cloud client folders) are off-limits for UI checks, Playwright and feature tests. Use a sandbox: a detached `git worktree` on port 1970 with its own `.env`, data copied from the fictitious dataset in `.claude/memory-private/dati-demo-cripto/` (procedure in its README), then remove the worktree. Never log in to real cloud accounts from the sandbox. Unit tests with `node --test` are fine: they use temp dirs.
