# Contribuire

Grazie per l'interesse a contribuire. Questo documento vale per qualunque forma di contributo: Pull Request via fork, patch inviata fuori GitHub (email, chat), accesso push diretto, o contributi non-codice (documentazione, traduzioni, screenshot, asset grafici).

## Licenza dei contributi

Contribuendo, accetti i termini del [CLA](CLA.md): il tuo contributo viene rilasciato sotto la licenza del progetto ([PolyForm Noncommercial 1.0.0](LICENSE)) e concedi all'autore (Danilo Priore) licenza a usarlo/rilicenziarlo, incluso per eventuali accordi commerciali futuri.

Per le Pull Request, la firma del CLA è gestita automaticamente da **CLA Assistant**: al primo contributo, il bot chiede la firma in un commento sulla PR. Firmato una volta, non va rifirmato per PR successive. Il merge resta bloccato finché il CLA non è firmato.

## Come contribuire via Pull Request

1. Fai fork del repository.
2. Crea un branch descrittivo (`fix/nome-bug`, `feat/nome-feature`).
3. Apri la Pull Request verso `main`.
4. Firma il CLA quando richiesto dal bot.
5. Attendi review dell'autore (obbligatoria, vedi `CODEOWNERS`).

## Altri canali di contributo

- **Patch fuori GitHub** (email, chat): stessa licenza del CLA si applica; l'autore conferma l'accettazione prima di integrarla.
- **Accesso push diretto** (collaboratori): stessi termini del CLA, concordati prima della concessione dell'accesso.
- **Contributi non-codice** (documentazione, traduzioni, screenshot, icone/asset grafici): stesso CLA, stessa licenza di rilascio.

## Casi particolari

- **Dipendenti/lavoro su commissione**: sottomettendo confermi di avere il diritto di farlo, non vincolato da un datore di lavoro che ne rivendica il copyright.
- **Minorenni**: serve consenso di un genitore/tutore legale prima della sottomissione.
- **Contributor anonimo/pseudonimo**: accettato, l'account GitHub è sufficiente per la tracciabilità.
- **Contributo generato/assistito da AI**: il CLA si applica sempre a chi apre la PR, mai al tool — resti responsabile del contenuto.
- **Fork che non contribuiscono indietro**: non richiedono CLA, ma restano vincolati dalla licenza del codice preso (vedi [LICENSE](LICENSE)).

Apri una issue usando il template appropriato. Per vulnerabilità di sicurezza, non aprire una issue pubblica: segui [SECURITY.md](SECURITY.md).
